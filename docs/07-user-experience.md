# 07 · Web 体验与智能指挥中心

## 交互原则

**一个指挥入口 + 多个专业视图 + 人工干预兜底**。自然语言优先，但任务、授权、项目与数据必须能够在无 AI 的情况下通过 Web 操作。

主要页面：

1. 首页：目标与项目进度、运行状态、优先级事项、待你审批、每日简报。
2. Command Center：自然语言查询、解释、规划、受控执行；多轮会话指代。
3. 项目与任务：目标、依赖、租约、检查点、事件链、成果、验收和恢复。
4. Agent 与执行环境：身份/账号/角色/能力/可达状态分别显示。
5. 记忆与决策：来源、版本、有效性、引用、纠正与知识发布。
6. 审批/安全/资源：权限、预算、危险操作预览、审计与异常。

## 自然语言控制

意图：查询、解释、规划、执行、调整、治理。先结合当前会话、页面焦点、权威业务状态与授权历史确定对象。对于“继续”“那个项目”“让他们停下”等模糊指令：

- 若对象和授权清晰，则按规则提出或执行。
- 对象存在多个候选或影响范围较大时，**询问一次必要澄清**或提供操作预览。
- 当前谈论架构时“继续”仅代表继续规划，不能自行开始开发/部署。

**操作计划生命周期**：解析用户意图 → 获取实时权威状态 → 规范化计划 → 权限/风险检查 → 必要确认 → 带幂等 ID 提交 → 验证结果 → 反馈状态。

确认预览时要重新检查资源版本与权限，避免预览后状态变化导致误操作。

## 呈现状态的诚实性

分清“请求已创建、已投递、已接收、已启动、已提交、已验收”和“未知”。Agent 自述与外部证据分开，显示最后验证时间；无法验证时不显示虚假实时运行状态。

通知三级：紧急安全/关键审批立即提醒；普通重要事项进入收件箱；日常事件进入摘要。每日简报必须基于真实任务、事件和成果引用。

## 人类体验目标

- 人的主要工作是设定目标、批准重要事项、纠正知识、处理异常，而非每天管理几十个执行线程。
- 能解释为何选某 Agent、为何暂停任务、参考了哪些证据；缺少事实时说明未知。
- 对不能撤销的行为不承诺撤销。例如邮件已发送无法靠取消任务收回。
- Command Center 是解释与操作入口，**不是绕开业务权限的超级管理员 AI**。
