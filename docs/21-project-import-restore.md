# 21 · 项目可携带包导入与恢复

此功能把 `otternest.export.v1` JSON 包恢复为当前 OtterNest 安装中的**新项目副本**。它适用于跨环境搬迁文字与结构化项目记录，不是 PostgreSQL 物理备份恢复，也不证明导入包是谁生成的。

## 操作流程

管理台「系统设置」提供文件选择、服务端预览和显式恢复确认。API 为：

- `POST /api/v1/projects/import/preview`，请求体 `{"bundle": <完整导出 JSON>}`。
- `POST /api/v1/projects/import`，请求体 `{"bundle": <完整导出 JSON>, "new_name": "可选的新项目名称", "confirm_restore": true}`。

两个接口都要求所有者身份。预览只检查，不写数据库；恢复在一个数据库事务中提交，失败时整体回滚。当前接受 `otternest.export.v1`、最多 10 MiB 的包。服务端校验 SHA-256、对象类型、重复 ID、DAG 自依赖/循环/最大前置数，以及任务、检查点、评审、成果等内部引用。恢复会为项目和其记录分配新 ID，因此不会覆盖原项目。

## 恢复后的治理状态

- 新项目为 `paused`。外部项目共享记录引用到的项目会成为无成员、无内容的 `archived` 占位项目。
- Agent 会创建新 ID 的禁用占位身份。只恢复名称和平台标签；不会导入令牌、登录状态或已核验能力。
- `completed` 和 `cancelled` 任务保留终态。其他非终态任务转为 `blocked`；原 `waiting_approval` 的 R3 任务保留待审批状态。所有任务的分配目标、审批授权和活动租约均清空/撤销，并递增非终态任务的租约 epoch。
- 副作用幂等台账保留已报告与对账状态。`pending` 或 `unknown` 副作用所在任务会被阻塞，不能通过执行恢复过程自动重放。
- 非归档记忆和 Skill 恢复为 `proposed`；决策恢复为 `proposed`，原审批说明标记为历史内容。Agent 第二轮审议记录保留为已关闭历史，自动评审员策略不会导入。
- Artifact 恢复名称、校验和、版本族和原验收备注元数据，版本状态重置为待本地复核，URI 指向 `unavailable://` 标记。原始文件字节未包含在 JSON 包内；调用者需要使用独立的文件备份流程搬迁内容。
- 事件作为 `imported.*` 历史记录保留，但不会创建对应的 Outbox 作业，不会重新投递旧 Webhook 事件。
- 不导入或触发 Webhook、A2A 远端端点、外部 Agent 任务、Secret、会话、真实平台令牌或本机运行环境配置。

恢复后，所有者需检查暂停项目中的数据和占位成员，补充本机信任与凭据，复核任务/知识，再单独决定是否启用项目和解除任务阻塞。任何输入包中的文本与评审均视为待复核数据。

## 完整性与真实性

导出包摘要对 `schema_version`、`exported_at`、`secrets_included`、`sha256_digest` 以外的规范 JSON 内容计算 SHA-256。恢复时重新计算并比较该值，以发现损坏或意外改动。SHA-256 未由可信签名密钥签署，因此不能证明包的来源或内容真实。管理员需在预览后确认是否信任其内容。

## 当前边界

该恢复入口不会覆盖已有项目、导入整个数据库、迁移二进制成果、自动重新接入第三方平台，也不会重建迁移目标环境的网络出口、密钥和 Agent 沙箱。生产级异地备份仍需要 PostgreSQL 与对象存储备份、密钥管理及经过验证的恢复演练。
