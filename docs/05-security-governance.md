# 05 · 治理、权限、安全与数据边界

## 最高治理原则

- 使用者是唯一最高管理员；Agent 无权提升自己的权限或修改根策略。
- 安全控制由**后端授权与运行环境机制强制实施**，不是仅靠提示词。
- 管理行为与执行行为分离；Agent/账号/执行实例/项目角色分离。
- 每个动作按身份、项目、数据敏感级别、任务授权、风险与预算执行 RBAC + ABAC 检查。

## 风险与审批

| 风险 | 示例 | 原则 |
|---|---|---|
| R0 | 授权范围内查询、整理 | 一般可自动 |
| R1 | 可恢复的低风险改动 | 按项目自治契约允许 |
| R2 | 重要文件/配置修改与审核 | 更严格证据、独立验证或明确批准 |
| R3 | 对外发布、付款、发邮件、不可逆删除 | 必须经系统所有者批准并核验结果 |

自我优化分类 E0–E4：从实验草案、项目 Skills、全局策略、核心代码到根权限与审计保护。E4 **不可由 Agent 自主修改或批准**。任何投票/协商都不能取消强制安全约束。

## 权限分配

- 任务临时凭据遵循最小作用域、最短适用期限；可委托任务不等于可转让管理员权限。
- 权限撤销后，旧令牌失效，但**不保证外部云端已读取的数据自动删除**。
- 负责人更换采用租约撤回 → 核实外部状态 → 标准交接 → 新授权 → 可信 checkpoint 恢复；不复制原 Agent 密钥/登录状态。
- 首次发现新 Agent 要验证可信来源、能力及环境后再入组。Agent Card 自称能力不能直接作为可信身份。

## 四层隔离

1. 项目数据隔离：跨项目只能通过授权的服务请求和知识发布机制共享。
2. Agent 隔离：独立身份、权限、日志和工作副本。
3. 执行环境隔离：独立主机/容器/受限 OS 用户，依据实际环境能力选择；**不同目录本身不是可靠安全边界**。
4. Secrets 隔离：登录信息、API Key、OAuth/浏览器 Cookie 不进普通上下文、公共记忆和工作日志。

同一 Muse 云端主机里运行多个 Codex 进程不代表彼此隔离；相同 OS 用户/主机管理员可突破文件夹隔离。运行沙箱能力需现场验证。

## 信任域与隐私

- **核心私有域**：控制平面、数据库、审批、凭据。
- **受信执行域**：经过环境隔离与身份验证、由使用者控制的执行节点。
- **外部云端域**：第三方云端 AI 平台，按任务提供最少数据与授权。

数据分级：公开、内部、机密、高敏感。外部云端可接收什么数据由政策与使用者授权决定，而非基于 Agent 的角色名称。

外部网页/文档/Agent 文字永远属于**不可信输入**，不得作为系统命令或篡改原任务授权。Agent Skills 和第三方插件需要来源、版本、审查、权限申明和沙箱策略。

## 审计与安全事件

- 保存操作发起者、授权、目标、前后状态、版本、证据引用、追踪 ID。
- 不在日志中长期存放明文凭据、敏感会话或非必要全量上下文。
- 异常时允许隔离执行者、撤销令牌、暂停新任务并记录排查结果。
- 外部执行环境清理需要独立核验；中央的“退役”标志不代表远程磁盘或登录会话已清除。
