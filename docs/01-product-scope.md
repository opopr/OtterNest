# 01 · 产品定位、边界与需求

## 目标

OtterNest 是**个人单租户**的分布式 AI 团队 OS。让一名系统所有者通过自然语言与管理后台，持续管理多个目标、项目、自治团队及异构 Agent；系统提供任务/权限/记忆/成果的统一权威状态，外部执行环境承担实际工作。

目标不是让每个账号都长期忙碌，而是使**成果质量与有效收益最大化，并减少人类管理负担**。

## 使用者与组织模型

- 当前只有一名最高管理员（系统所有者）。
- 拥有多个项目工作空间；各空间有自治契约、目标、成员、记忆、成果、预算、审批规则。
- 中央治理 + 项目级自治 + 动态 Agent 角色（协调者、执行者、独立审核者、顾问、后备协调者）。
- **账号 ≠ Agent ≠ 执行实例 ≠ 项目角色**，四者分别标识。
- 一个 Muse 云端环境可包含 Codex CLI 等工具，但彼此的身份与权限不可据此自动继承。

## 基础能力（保持可靠、不可依赖高级 AI）

1. 项目、目标、任务生命周期、依赖关系、优先级和明确验收标准。
2. Agent 注册、身份/连接状态、验证能力、角色及独立权限。
3. RBAC/ABAC 与任务级临时授权、审批和审计。
4. PostgreSQL 权威状态、版本化成果存储、项目边界。
5. 结构化记忆管理与按权限生成 Context Packet。
6. 可靠事件投递、重试、状态一致性、租约/检查点/交接/恢复。
7. 私人 Web、人工接管、停止与降级控制。

## 高级能力（可按项目、按策略启用）

- 自主发现子目标、提出任务与组织有界的任务 DAG。
- 多 Agent 协商、证据检验、独立交叉审核、异议机制。
- 动态团队编成与按能力/环境/质量/预算的调度。
- Portfolio 多项目优先级、公平调度、受控跨项目协作。
- Skills 与知识发布、质量评估、规则实验及受控自我优化。
- AG-UI/A2UI 深度交互和更复杂的语义搜索。

## 明确不采用或不保证

- 不以 QwenPaw、n8n、GitHub 或 Telegram 为**必备中央工作流**。GitHub 可以作为文档/代码仓库，不是运行时的强制中央依赖。
- 不以服务专用定制适配器为首选路线；优先标准协议和通用执行器。
- 不直接汇总或规避多个付费订阅的使用限制；Plus / AI Pro 等订阅并非可自由调用的 API 池。
- 不承诺所有外部 Agent 都能被 Webhook/A2A 自动唤醒或在后台持续运行。
- 不预建复杂多租户 SaaS、十几个微服务，也不要求全部高级能力首日同时运行。
- 不让 Agent 绕过最高权限、安全策略、日志保护和人工审批。

## 产品成功标准（定性与可测）

- 从明确目标到可信成果有闭环：来源、任务、执行、证据、审核和归档可追溯。
- 授权范围内的自主行为能够减少人工频繁分配与粘贴上下文。
- 即使 Muse、Codex 或某模型不可用，已保存的工作和个人后台仍可受控访问。
- 多 Agent 相较单 Agent 的增益必须经过对照评价，而不是仅看“参与者数量”。
- 对未知状态、缺失数据及不可验证的第三方行为显式标注未知。
