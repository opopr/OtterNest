# 16 · 受控指挥中心与独立决策复核（migration 0008）

## 实现范围

这一轮实现**结构化管理员命令**的预览/确认闭环，以及 Agent 对决策的**独立证据与异议**记录。**尚未实现自然语言解析、模型驱动的计划器、多轮自动辩论或独立证据真实性验证**。把这些显式区分，有助于防止模型误将文本解释为管理员的自动授权。

### 操作预览

管理界面新增“操作预览”页；API：

1. `POST /api/v1/command/plans`：所有者针对一个任务提交明确动作（`authorize_task`、`review_task`、`route_task`、`cancel_task`）。保存预览，记录目标任务的当前 `version`，生成十分钟有效期；**此时不执行任务状态变更**。
2. `GET /api/v1/command/plans/{id}`：所有者查看待确认/已执行状态。
3. `POST /api/v1/command/plans/{id}/confirm`：数据库锁住命令计划和目标任务，再校验权限、版本、当前项目状态、外部委托边界及操作条件。确认成功后提交一次业务事件、一条 `command.executed` 事件，并保存执行结果；重复确认返回原结果。

预览无法当作永久授权。状态/版本已改变或超过有效期的预览返回 **409**，必须重新预览。R3 操作仍须由所有者主动确认；Agent 不可创建或确认计划。取消任务**不能保证**已在外部运行的进程真的停止；若存在不确定的 A2A 委托，阻止直接取消。

规范化的操作参数写入 JSON 列，动作使用服务端白名单，禁止传入其他字段。未来接入自然语言时，模型只能生成待验证的*候选结构化动作*，不得跳过 `confirm`。

### 多 Agent 独立观点

- 只允许已启用且属于项目的 Agent 对未批准决策提交立场：`support`、`oppose`、`alternative`，携带推理和有限数量的证据引用。每个 Agent 对同一决策只提交一次。
- `POST /api/v1/decisions/{id}/reviews` 由 Agent 调用；`GET` 由所有者读取。决策批准前，Agent 不可读取其他人的观点，以减少锚定和相互抄袭。
- 异议/替代方案不是自动否决票，也不改变管理员权限。存在异议时，原 `approve` 路径会拒绝直接批准；使用者需在 `POST /api/v1/decisions/{id}/resolve` 写入至少十字符的实质处理说明。
- **证据引用是 Agent 自述，默认未经外部核实**。只有单次独立意见记录，尚没有多轮辩论、证据质量评级或自动达成一致的机制。
- 决策批准后项目成员可查看最终独立意见；外部/跨项目 Agent 不可读取该项目决策或评论。

## 并发与持久性

新增 `command_plans`、`decision_reviews`，并为 `decisions` 增加 `owner_review_note` 字段。使用 Alembic `0008` 正式迁移。新指令流与现有事件/Outbox/审计保持事务一致。

单元测试检查拒绝越权、无效参数、预览过期、版本变更、重复确认、跨项目评论及异议审批；GitHub PostgreSQL 测试检查竞争的不同命令计划只能有一个成功执行。

## 未实现与后续工作

- 接入有可靠来源的 LLM 意图解析、消歧、可读操作 diff，但保持最终服务端检查与人类确认。
- 更完整的策略 DSL、审批工单和 R0–R3 自动授权白名单。
- Agent 群组讨论轮次、独立证据核验、质量评估及决策的时效性/撤回。
- 实际服务器部署、安全边界评估及平台互操作测试。
