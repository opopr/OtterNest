# 03 · 领域模型与数据规则

以下是**概念数据契约**，不是已实现的数据库 Schema。

## 核心实体

| 实体 | 必须表达的信息 |
|---|---|
| Account | 平台、账号引用、计划用途、授权/订阅状态；不直接保存明文密钥 |
| Agent | 唯一身份、声明能力、验证能力、信任状态、授权范围 |
| Runtime / Instance | 环境、宿主、工具、是否可连接/已启动、心跳、支持的协议 |
| Team Membership | 项目、Agent、角色、有效期、责任范围 |
| Project / Charter | 目标、自治等级、预算、敏感级别、决策边界、停止条件 |
| Goal | 可衡量结果、优先级、检查周期、完成条件 |
| Task | 项目/目标、责任人/执行人、依赖、状态、验收、风险、授权上下文 |
| Task Attempt / Lease | 执行代次、租约、fencing token、checkpoint、确认状态 |
| Event / Delivery | 事件与因果 ID、版本、发件箱、订阅、重试、投递/确认状态 |
| Artifact | 文件引用、内容校验、版本、创建者、项目 ACL、测试证据 |
| Memory Record | 类型、作用域、来源、可信度、有效期、版本、敏感级别 |
| Decision Record | 议题、选项、证据、异议、结果、批准者、重议条件 |
| Approval / Audit | 申请、批准范围、决定者、时间、证据、审计轨迹 |

## 任务状态与执行

概念状态包括：草案、就绪/待依赖、已分配、已领取、运行、待审批、阻塞、已提交/待验收、完成、失败、取消。任务状态由**统一业务内核**转换，事件不可自行覆盖权威状态。

- 并发领取采用事务性 claim；租约、heartbeat 和 fencing token 防止旧执行者写入新代次结果。
- 执行实例身份与任务责任人不同；前者可因失联而被替换，后者责任关系不丢失。
- 跨主机恢复只从**最近已验证并保存的 checkpoint** 开始；不声称模型隐含对话状态可跨平台迁移。
- 外部副作用要求去重/幂等键及结果核验；未知结果不得盲目重试。
- 委托深度、重复任务、时间和预算有界，避免循环自激。

## 事件与一致性

- 事件事实、命令请求、任务承诺、普通消息分离。
- 事务性 Outbox：业务变更与待发布事件在一个 PG 事务提交。
- 默认考虑“至少一次”投递、重试、幂等消费者、死信记录；不承诺跨外部系统端到端 exactly-once。
- 同一实体的关键状态通过实体版本/序号校验；跨实体事件不假设天然全局有序。
- 重放原则上仅用于状态重建或诊断，外部副作用不自动重放。

## 记忆与上下文

记忆类型：事实、决策、过程/情节、技能/程序、经验教训、不可改动的原始证据。作用域：全局已发布、项目、Agent 私有、任务、来源证据。

知识生命周期：`Proposed → Verified → Published → Revised / Archived`，允许争议、过期或撤回状态。记录出处、版本、时间有效性、敏感度及权限。

**Context Broker** 依据任务目标、执行者、权限、上下文版本与 token 预算组装上下文包。外部上传的文字视为数据，不得提升为系统指令。跨项目共享使用“审核后发布”，而不是开放原项目全部记忆。

## 成果与交接

**Task Handoff Package** 包括：目标、范围、任务、验收条件、决策、依赖、运行环境说明、权限边界、工件引用、测试证据、最后可信 checkpoint、版本、待解决风险。

成果按工作副本 → 不可变版本 → 所有者验收/驳回管理，防止覆盖已审文件；当前实现为同名版本族和 5 MiB 本地文件，跨机二进制备份与恢复仍需补齐。可使用本地 Git，但不依赖 GitHub 作为运行时基础设施。

## 数据可携带性

- 项目、任务、决策：JSON/CSV；记忆：Markdown/JSON；事件：JSONL；Skills：SKILL.md 及资源。
- 文件按原格式导出，提供校验和；PG 需要可恢复备份。
- 数据删除应考虑附件、日志、备份保留窗口与第三方已接收的副本，不可承诺远程同步删除。
