# 08 · 质量验证、资源管理与受控自我优化

## 质量验证五层

1. **任务成果**：完成 ≠ 验收 ≠ 达到最终业务效果。
2. **Agent 能力**：按任务类型、当前环境、样本和成功证据评价，而非一个总体“智商分”。
3. **协作价值**：多 Agent 相比单 Agent 是否提高质量、降低返工，是否值得额外时间与资源。
4. **知识/决策质量**：检索准确、证据来源、过期与异议、实际验证。
5. **系统可靠性**：恢复成功、审计完整、越权阻断、数据一致性。

自动化测试、独立 Agent 复核、人工验收按风险组合。重要结论优先原始证据及真实测试，不以 Agent 自我评价代替验收。

## 指标与归因

建议观测：验收通过率、重复/返工、交接成功率、执行和等待时间、外部状态未知率、恢复成功率、预算消耗、人工介入时长。记录样本量、测量窗口、任务难度与可验证程度。

失败归因允许多原因：上下文过期、任务定义不足、执行依赖缺失、模型错误、外部服务故障、验收标准问题等；不要无证据地降低单 Agent 评价。

## 资源与预算

调度顺序：身份/权限 → 能力 → 环境 → 可用性 → 质量/成本/时效/公平性。

预算包括：项目任务数、并发、时间、重试/讨论轮次、已知 API 成本、固定订阅成本。订阅余量若无可靠接口应显示**未知**，不得假定剩余额度或设计规避平台限制的轮换机制。

## 可观测性与备份

- 统一 trace/correlation ID 关联项目任务、工具调用、事件、交接、审查与审批。
- 分开报告可连接、已接单、已启动、运行中、失联、外部状态未知。
- 数据库、附件、凭据/配置的备份与恢复边界应清楚；定期恢复演练比“有备份”更重要。
- 中央控制平面是单点故障，计划合理的备份/恢复策略，不虚称高可用。
- 运行正常、降级、保护三种模式，支持单一外部服务故障下核心后台继续可用。

## 受控自我进化

观察 → 提案 → 候选版本 → 隔离实验 → 独立验证 → 按权限审批 → 受控发布/回滚。

适合优化：Skills、上下文模板、记忆检索、任务调度与工作流规则；**核心授权、审计保护、系统宪章不能由 Agent 自行更改**。

固定评估集 + 未见样本 + 安全硬门槛；实验可采用历史任务，但涉及外部副作用的操作不能实际回放。任何提升都需验证没有引入越权或数据泄露。

## 有关实施的定位

这里记录的是未来评估与运维的**要求**，不是部署手册，也不是执行计划。本项目当前未进入构建阶段。
