# 09 · 架构决策记录（ADR 汇总）

> 以下为讨论已确定的**规划决策**，不是已完成的工程验证或安装结果。

| ID | 决定 | 主要理由与边界 |
|---|---|---|
| ADR-001 | 项目命名为 **OtterNest（小水獭窝）**，仓库建议 `otternest` | 可爱的动物主题，强调分布式协作和私有中心 |
| ADR-002 | **个人单租户**、多个项目工作空间 | 满足个人使用，避免无谓 SaaS 复杂性 |
| ADR-003 | **Oracle ARM 1C6G** 作为轻量控制平面 | 现有资源明确；不承担高负载模型/构建工作 |
| ADR-004 | 采用 **PostgreSQL + 文件存储** | 共享事务状态、结构化数据、审计和版本；pgvector 可选 |
| ADR-005 | **模块化单体**优先 | 1C6G 资源有限、减少运维与跨服务一致性成本 |
| ADR-006 | **三平面**：交互、控制、执行 | 保持治理稳定、执行环境可替换 |
| ADR-007 | **中央治理 + 项目自治 + 动态角色** | 支持主动协作但保留最高人类控制权 |
| ADR-008 | MCP、A2A、OpenAPI、Webhook、Skills、SSE/WS、AG-UI、A2UI | 采用标准互操作、按阶段能力增强，不复制业务内核 |
| ADR-009 | RBAC + ABAC + 任务级临时授权 | 细粒度授权、最小权限、可审计和可撤销 |
| ADR-010 | 目标/任务/事件/记忆/成果集中保存权威状态 | Agent 可离线，不能把聊天上下文当作唯一数据源 |
| ADR-011 | 任务需 lease、checkpoint、fencing、幂等和审慎重试 | 失联接管、安全恢复、避免僵尸执行与重复副作用 |
| ADR-012 | 知识来源、审核发布、版本、敏感级与 Context Broker | 减少幻觉、过期知识和跨项目污染 |
| ADR-013 | 有界的多 Agent 协商及独立验证 | 证据优先，不以多数投票替代事实与授权 |
| ADR-014 | 事件持久化和事务性 Outbox | 防止事件丢失；不依赖内存通知实现可靠队列 |
| ADR-015 | 私人 Web + 自然语言 Command Center | 易使用、可解释，且关键功能可人工操作 |
| ADR-016 | 高级自治、调度、实验等按需启用 | 控制复杂性，保证基础系统可独立运行 |
| ADR-017 | 不依赖 GitHub、n8n、QwenPaw、Telegram 作为中央运行时 | 减少强制外部依赖，GitHub 可仅用作项目仓库 |
| ADR-018 | 保留其他 Oracle VM 的用途为开放问题 | 不提前绑定备份或执行职责 |
| ADR-019 | 严格区分已连接订阅账号与可自动执行的 Agent | 平台实际支持能力需验证；不能虚构 API 或唤醒能力 |
| ADR-020 | 系统策略可被建议改进，根治理规则不可由 AI 擅自变更 | 可持续优化但不牺牲用户控制与安全 |

## 变更程序

重要决策的变更需提交记录：原决定、为什么不再成立、候选方案、证据、风险、涉及项目、批准者与时间。Agent 只能在现有授权下提出变更，不自动改写已确认决策。
