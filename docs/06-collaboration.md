# 06 · 自治、协作、决策与事件

## 自治框架

目标 → 发现机会/问题 → 提案或任务 → 授权/调度 → 执行 → 验证 → 形成知识 → 检查目标。

项目层拥有 **Project Charter**：目标、验收、角色、数据范围、预算、决策边界、暂停/终止条件。项目可以动态组队；系统层保留全局治理与资源分配权。

## 角色与能力

- 角色可按任务变化：协调、执行、审查、研究、顾问、后备负责人。
- Agent 声称能力与已验证能力分开，能力验证需绑定当前环境和有效期。
- 只有具备真实 Runner/远程端点/可轮询能力的 Agent 才能被系统自动分配实际执行任务。
- 动态团队组建根据能力、权限、环境、可用性、历史质量、截止时间和成本；**权限/能力/环境/可用性为硬约束**。

## 结构化协商

提案 → 独立分析 → 证据收集 → 交叉质疑 → 有界协商 → 决策授权 → 验证。

- 常规任务不强制多 Agent 开会；重要分歧才开启协商，默认考虑最多两轮。
- 共识是意见，不是事实；相似模型之间的错误可能相关。
- 异议分普通异议、重大异议、安全阻断。强制策略不能经投票绕过。
- 决策记录保留：议题、上下文版本、选项、证据、假设、异议、风险、批准人、有效期、触发复查条件。
- 已定的 PostgreSQL 等架构决策，任何后续更改必须作为**变更提案**而非重新从零覆盖。

## 事件驱动工作流

区分 Event（已发生事实）、Command（行动请求）、Task（被追踪的工作）、Message（交流）。

事件类型：项目/目标、任务、Agent 状态、记忆变更、审批、预算、质量/异常。可按项目、订阅者、数据权限和角色过滤。

- 事务性 Outbox + 持久化重试/死信 + 幂等处理，防止状态改变却丢消息。
- 时间、条件、组合、人工和状态变更触发均受项目预算与安全限制。
- 设置委托深度、重复任务阈值、无进展阈值、循环检测与熔断；停止旧规则版本变更带来的意外重放。
- 事件与任务状态时间线可追溯，但外部不可逆动作不自动重放。

## 多项目管理

- 全局项目组合按优先级、资源配额、截止时间和公平性调度；避免高优先级永久占满资源和低优先级长期饥饿。
- 跨项目协作通过授权的 Cross-Project Request 和成果发布；不直接开放另一项目的原始记忆或凭据。
- 项目草案、授权、活跃、暂停、休眠、完成、终止有清晰状态。
- 关键中断/暂停是**控制平面停止新调度**，是否中止第三方正在运行的流程需单独确认。
