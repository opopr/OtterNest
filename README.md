# 🦦 OtterNest · 小水獭窝

> **个人自托管的分布式 AI 团队操作系统**  
> Personal AI Team OS · Local-first ownership, distributed execution.

**项目状态：总体产品与架构规划已收口；尚未开始开发或部署。**  
**文档基准日期：2026-11-13。**

## 名称与愿景

**OtterNest**（小水獭窝）：像一群各有所长、善于协作的小水獭一样，AI Agent 可以在不同的云端或本地环境工作，却在一个由使用者掌控的“窝”里共享目标、授权的知识、任务和成果。

OtterNest 不是某一个 AI 模型，也不负责“把多个订阅额度合并为 API”。它提供个人控制平面，组织多个已具备实际可调用/可接单能力的 Agent 形成受治理的工作团队。

一句话定位：**目标驱动，长期记忆，标准互操作，分布式执行，个人掌控。**

## 已确定的原则

- **个人单租户**，支持多个项目空间、自治 AI 团队、独立 Agent 身份；未来可演化，但暂不建设 SaaS 多租户体系。
- **轻量控制平面**：选定一台 Oracle Cloud ARM 1 vCPU / 6 GiB VM；PostgreSQL 为权威数据库；文件保存大型成果。
- **模块化单体**优先，不预设 Kafka、RabbitMQ、Redis 或大量微服务。
- **分布式执行**：Muse、Codex、Google AI、其他云主机或自建执行节点承担实际模型推理、浏览器操作、代码构建与测试。
- **人类拥有最高治理权**：AI 可自主规划和委托，但不得越权、自行扩权或规避审批。
- **遵循真实平台能力**：MCP/A2A 不是万能远程唤醒器；订阅账号不天然提供后台 API；不能把“已投递”当作“已执行”。
- **自由替换平台**：任务、记忆、决策和成果保留在个人控制的数据系统内，避免被某个 AI 厂商锁定。

## 三大平面（逻辑）

```text
[使用者]
  └─ Interaction Plane：私人 Web / Command Center / 审批与可视化
          │ 受控业务 API
  ┌───────▼───────────────────────────────────────────────┐
  │ Control Plane：Oracle ARM 1C6G · 模块化单体           │
  │ 目标/项目  任务/事件  Agent/团队  记忆/上下文         │
  │ 授权/审批  成果/版本  决策/审计  资源/质量           │
  │ PostgreSQL + 文件存储                                 │
  └───────┬───────────────────────────────────────────────┘
          │ MCP / A2A / OpenAPI / Webhook / SSE 等
  ┌───────▼───────────────────────────────────────────────┐
  │ Execution Plane：Muse / Codex / Google AI / 其他节点 │
  │ 仅在其真实支持的连接、触发与权限范围内工作             │
  └───────────────────────────────────────────────────────┘
```

## 确认过的硬件条件

- Oracle Cloud 4 台 VM：**2 台 AMD x86（各 1 vCPU / 1 GiB）**；**2 台 ARM（各 1 vCPU / 6 GiB）**。
- 其中一台 ARM 1C6G 作为中央控制平面；其余机器的角色**尚未决定**。
- 不在中央 1C6G 主机上运行大型语言模型、浏览器自动化或高负载编译测试。

## 当前状态与范围

本仓库目前**仅包含需求、架构及治理设计文档**。不包含业务代码、可运行部署脚本、第三方服务凭据，也不宣称任何第三方云 Agent 已成功接入。

**不要把规划中的“能力”误认为已经存在的“平台接口”。** 具体可行性见 [待验证事项](docs/10-open-questions.md)。
